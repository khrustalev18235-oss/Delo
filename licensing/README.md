# Дело №308 — ручная оплата и лицензии

**Статус:** исходники серверной системы готовы к развёртыванию; сервис не запущен, платная игра ещё публична. Не принимайте деньги до завершения переноса и проверки.

## Архитектура
- Бесплатная глава: публичный GitHub Pages `/demo/`.
- Покупатель переводит деньги **вручную** по реквизитам, которые владелец сообщает лично; сервис не проверяет факт оплаты.
- Владелец сверяет поступление денег в своём банке и создаёт код через защищённый административный API.
- Код одноразовый. Сервер хранит только SHA-256 хеш кода, а не сам код.
- При активации сервер устанавливает HttpOnly/Secure cookie с сессионным токеном. Полная версия и её ресурсы выдаются только из **закрытого Cloudflare R2** после проверки сессии в D1.
- Срок сессии 365 дней. Повторный доступ после потери cookie/смены устройства пока не реализован: для продаж нужна отдельная процедура восстановления лицензии.
- Нет антибрутфорс-лимитов на уровне приложения: **обязательно** настройте Cloudflare WAF rate limiting для `/api/redeem` и `/api/admin/*`. Не считайте один CORS защитой админки.

## Настройка (Cloudflare)
1. Создайте D1 базу `delo308-licenses` и приватный R2 bucket `delo308-private-game`.
2. Скопируйте `wrangler.toml.example` в `wrangler.toml` и укажите D1 ID. Не включайте публичный доступ R2.
3. Выполните `npx wrangler d1 execute delo308-licenses --remote --file=licensing/schema.sql`.
4. Создайте длинный случайный секрет: `npx wrangler secret put ADMIN_SECRET`. Не записывайте его в репозиторий.
5. Разверните Worker: `npx wrangler deploy --config licensing/wrangler.toml` (путь конфига подстройте под рабочую директорию).
6. **До продаж** удалите платные главы из публичного репозитория и из публичной истории GitHub (или заведите новый чистый публичный репозиторий только с демо), отключите публичный маршрут `/complete/`. Простое удаление текущего файла не очищает историю коммитов.
7. Соберите отдельную приватную платную версию игры. Перепишите относительные пути ассетов под `/assets/`, загрузите `index.html` и необходимые `assets/*` в R2. Никогда не загружайте платный бандл в публичный GitHub Pages.
8. Настройте публичную страницу активации `/activate/` на GitHub Pages и укажите URL вашего Worker в `activate/config.js`. Укажите получателя перевода только после согласования с владельцем.
9. Настройте HTTPS, WAF rate limiting, тестируйте активацию/повторное использование кода/отзыв лицензии/запрет доступа без cookie.
10. После проверки поступления оплаты администратор создаёт код:
```bash
curl -X POST "https://YOUR-WORKER.example/api/admin/issue" \
  -H "Authorization: Bearer YOUR_ADMIN_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"note":"заказ 001, оплата подтверждена"}'
```
Верните покупателю поле `code` **один раз**. Административный секрет никогда не отправляйте покупателю.
Для отзыва используйте `POST /api/admin/revoke` с JSON `{"code":"D308-..."}`.

## Известные ограничения
- Ручная проверка платежей, без автоматической интеграции банка.
- Нет восстановления доступа на другом устройстве.
- Пользователь может сохранить полученный HTML/JS после законного входа; абсолютной DRM-защиты у браузерной игры нет.
- Приватное хранилище и Cloudflare аккаунт требуют настройки владельцем.
- Текущая публичная полная версия остаётся открытой до отдельной миграции.
