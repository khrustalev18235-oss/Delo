# Архив №308 — Telegram-бот и Mini App

Исходники бота и API продажи игры «Дело №308: Последний гость».

## Возможности
- /start — кнопки демоверсии, полной игры и информации о покупке
- оплата **Telegram Stars** (XTR) с проверкой `successful_payment`
- сохранение прав доступа по Telegram user ID в SQLite
- Mini App с серверной проверкой подписи Telegram `initData`
- выдача **полной игры только из приватной директории сервера**, не из GitHub Pages
- сохранение/загрузка прогресса на сервере для купивших игроков

## Настройка
1. Создай отдельный сервер с HTTPS-доменом (reverse proxy на `127.0.0.1:8000`).
2. `cd telegram && python -m venv .venv && source .venv/bin/activate` (Windows: `.venv\\Scripts\\activate`).
3. `pip install -r requirements.txt`.
4. Скопируй `.env.example` в `.env` и задай `BOT_TOKEN`, `PUBLIC_BASE_URL`, цену в Stars и `FULL_GAME_DIR`.
5. Полную сборку `complete/index.html` размести **в приватной папке на сервере**, не в публичном репозитории. Перед запуском продаж удали/закрой публичную `/Delo/complete/` и любые публичные копии полной игры. Скрытие URL не является защитой.
6. Запусти `python app.py`; приложение слушает `127.0.0.1:8000`. Для Telegram Mini App нужен доступный HTTPS.
7. В @BotFather установи домен Mini App и, при желании, кнопку меню с адресом `https://YOUR-DOMAIN/app`.

## Проверка
- `GET /health` — проверка сервиса
- `/start` в Telegram — меню
- кнопка «Демоверсия» открывает публичную первую главу
- кнопка «Купить» выставляет счёт в Stars
- **только после** Telegram `successful_payment` появляется право на полную игру
- кнопка «Полная игра» открывает `/app`; браузер внутри Telegram отправляет `initData` для проверки

**Важно:** текущий backend — MVP, не релизная платёжная инфраструктура. До реальных продаж нужны тестирование возвратов Stars, поддержка покупателей, резервное копирование SQLite, настройка логов, rate limiting, мониторинг, политика конфиденциальности и надёжное HTTPS-развёртывание. Цена в примере — заглушка, не согласованная стоимость.

## Архитектура
Бот и веб-сервер работают в одном Python-процессе. Bot использует long polling. `/api/auth` выдаёт короткоживущий cookie после проверки подписи Telegram `initData`. `/full` и `/api/progress` требуют cookie и подтверждённой покупки. Доступ к HTML защищён, но полноценная защита контента требует также ограничения всех зависимостей и удаления публичных копий. Для продажи как лицензии, а не защиты от копирования, этого обычно достаточно.
